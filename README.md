# CSP4TECH Website (rebuild)

A from-scratch rebuild of csp4tech.com — plain HTML/CSS/JS, generated by a
zero-dependency Node.js script (no npm packages required, nothing to
`npm install`). 66 pages: home, about, services, contact, Zoho suites
comparison, 39 individual Zoho product pages, and a 20-post blog.

## Why this structure

The site content (company stats, product descriptions, blog posts) lives in
plain JS data files under `generator/data/`. A small build script
(`generator/build.js`) turns that data + the HTML templates in
`generator/templates/` into static `.html` files in `dist/`. You never hand-edit
HTML directly — you edit the data, and rebuild.

This means: no React, no Tailwind, no build tool to install, no dependency
updates to manage — and it fixes the two structural issues found in the old
site's audit (a wrong `mailto:` link and contradictory stats on different
pages), because now there is exactly **one place** each fact lives
(`generator/data/config.js`), not one per page.

## Local preview

You need Node.js (any recent version) installed — nothing else.

```bash
npm run build        # regenerates dist/ from the data + templates
```

Then open `dist/index.html` directly in a browser, or serve it locally:

```bash
python3 -m http.server 8080 -d dist    # or: npx serve dist
```

## Deploying to Vercel

1. Push this folder to a GitHub repo (or drag-and-drop the folder into
   Vercel's dashboard — either works).
2. In Vercel, "Add New Project" → import the repo.
3. Vercel will detect `vercel.json`, which already sets:
   - **Build command:** `node generator/build.js`
   - **Output directory:** `dist`

   No further configuration needed — click Deploy.
4. Once deployed, go to your Vercel project → **Settings → Domains** and add
   `csp4tech.com` and `www.csp4tech.com` (no `.in`). Vercel will show you the
   DNS records (usually an `A` record for the apex domain and a `CNAME` for
   `www`) — add those at your domain registrar. Propagation is typically
   minutes to a few hours.
5. **Important:** the old `.com.in` domain is a separate registration from
   `csp4tech.com` — this project doesn't touch it. If you want visitors on
   the old domain redirected to the new one, that redirect has to be set up
   wherever `csp4tech.com.in` is currently hosted (or you point that domain
   at this same Vercel project and add a redirect rule there too — ask if
   you want help with that).

## What's already fixed from the audit

- The contact page's "email us" link no longer points to `shyphan.com` (a
  third-party domain from the old template) — it's a plain `mailto:` to
  `info@csp4tech.com`, generated from the single `config.js` value, so it
  can't drift out of sync again.
- All company stats (founded year, businesses served, apps implemented) come
  from one object in `config.js` and are used identically on the homepage
  and About page — no more 2016-vs-2018 or 4,000-vs-135 contradictions.
- Business hours appear once, from `config.js`.
- Canonical domain is set to `csp4tech.com` (no `.in`) throughout — meta
  tags, sitemap, and `og:url` all use it.
- No `shyphan` references anywhere (verified — see `checklinks.js`).

## Things that still need your input

- **"Trusted by" logos**: currently plain text placeholder badges (`Your
  Client Co.`, `Partner Group`, etc.) in the homepage's trusted-by strip —
  see `generator/data/config.js` → `trustedByPlaceholders`. Replace that
  array with your real client names, and swap the placeholder `<div>` in
  `generator/templates/home.js`'s trusted-by section for `<img>` tags once
  you have logo files and permission to display them (drop the image files
  in `generator/assets/` and reference them as `/images/yourlogo.png`).
- **Contact form backend**: the form on `/contact-us.html` is a static
  front-end with client-side validation only — it doesn't send anywhere yet.
  Point it at your Zoho Forms embed, a Zoho CRM webhook, or a serverless
  function before launch (see the comment in `generator/assets/main.js`).
- **Offices**: the old site listed Beirut, Riyadh, and Noida offices, which
  didn't match the "Lebanon-based" positioning elsewhere on the site (and
  contributed to the `.com.in` domain confusion in the audit). This rebuild
  only lists the Beirut HQ. If the Riyadh/Noida offices are real and should
  be shown, add them to `generator/data/config.js` and the contact page
  template.
- **Blog count**: the old site had 26 posts, all dated one-per-day across a
  three-week span (flagged in the audit as reading like bulk-generated
  content). This rebuild ships 20 posts — all on topics confirmed from the
  old site, rewritten from scratch, with dates spread naturally across
  ~7 months instead. Add more in `generator/data/blog.js` any time; each
  post is just an object in that array.
- **Real product screenshots/icons**: product pages currently use text and
  icon placeholders (✓, checkmarks) rather than Zoho's own screenshots or
  logo — intentional, to avoid using Zoho's trademarked assets without
  their own brand guidelines/permission. Swap in Zoho's official partner
  marketing assets if you have access to their partner portal.

## Adding or editing content

- **A product**: add an object to `generator/data/products.js`, run
  `npm run build`. Its page, nav entry, and footer link are generated
  automatically.
- **A blog post**: add an object to `generator/data/blog.js` in the same
  `{ slug, title, date, excerpt, readTime, body }` shape as the existing
  ones, run `npm run build`.
- **Company info (email, phone, hours, stats, address)**: edit
  `generator/data/config.js` — every page pulls from this one file.
- **Visual design**: `generator/assets/style.css` — plain CSS custom
  properties at the top control the color palette, spacing, and radius
  scale site-wide.
